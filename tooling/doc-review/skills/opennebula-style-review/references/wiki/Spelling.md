## Spelling and Punctuation

Follow US English spelling and punctuation rules.

If in doubt about spelling, refer to the [Merriam-Webster Dictionary](https://www.merriam-webster.com/).

For punctuation, use double quotes and punctuation marks inside the quotes. For instance:

> This is known as “VNF.”

## Footnotes Punctuation

Treat the footnote reference number as if it were a closing quote: place it outside a comma or period if any of these are present. Example:

> ... has achieved a 95% success rate.<sup>2</sup>

## Hyphenation

Hyphenate compound adjectives, such as: “High-Availability clusters,” “multi-user environment,” etc. Don’t hyphenate compound nouns, e.g. “If you require high availability, then…”

Examples of hyphenated terms:

* Front-end  
* bare-metal if used as an adjective (e.g. “on bare-metal hosts”)  
* on-premises if used as an adjective (e.g. “an on-premises deployment”)

## Text Styles: Bold, Italic

If you want to emphasize a feature, GUI element or component name use **bold text**. Examples:

>Using the Sunstone Web UI, you can...

> In the left-hand pane, select **Storage**, then **Datastores**.

If instead you want to emphasize a *concept* or *key point*, use *italics* (like in this sentence and in the example below):

> Check the *private* IP of the VR.

When referencing literals such as names of files, variables etc. include them in the `code` format, as is already done in the existing OpenNebula docs. Examples:

> To check the state of the VMs, run `onevm list`. In the file `/etc/one/oned.conf`, find the `FEDERATION` section...
